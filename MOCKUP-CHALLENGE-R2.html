ARENA NEEDS PRO · layout 0x10+ (free build)
Arena preview + opponent pane stay visible (firmware hidden, as always); RUN is locked:
ARENA NEEDS PRO — UNLOCK TO PLAY
Gating is at playback + builder menu only, never at parse (§9.3). v1 ships no Pro ids.
Playback reuses RUN
RUN builds the World from the descriptor — fixed spawns / SCATTER, per-slot HP, code seed, timed limit, Bot.fromBinary for pinned slots, assembled local firmware for open slots. The existing arena + execution monitor render it tick-for-tick. Free-play start() is untouched.
Result capture (feeds R3)
On finish the actual outcome — winner (relative to the code's slots), ticks, loser end_hp — is stored in activity-local state. R2 shows it in the RECORD badge; R3 reads it to unlock SEND BACK and the history.
Opponent firmware — hidden in v1
The program is not shown on the challenge screen and there is no reveal button. Reading it is the hacking axis: decode the base32 → parse the fw block → disassemble the triples. Display-layer only — no eng bump. v2: sender-chosen reveal is a format change (a flags bit / field).
Saved codes (R2 — SAVE → .chc)
SAVE writes the canonical base32 code string (RF1-…) into a dedicated codes table in the existing botfiles SQLite store (name = LABEL.chc) — not the firmware files table, so a code is never fed to the bot cycle. DIR lists both (firmware stays bare, e.g. TURTLE); EDIT opens a .chc to read the code — base32, the artifact, not a firmware reveal (v1 §4.1 holds). Re-open re-validates (§11). This is the store R3's history manages over (§9.3). No eng / format impact.
